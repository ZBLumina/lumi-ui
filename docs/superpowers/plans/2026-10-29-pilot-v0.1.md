# Lumi UI Pilot v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first reusable Lumi UI mini-library and a standalone Potassium test bundle.

**Architecture:** Source is split into focused Luau modules for mounting, theme tokens, primitives, window/navigation, and controls. A small entry module exposes the public API, while a standalone pilot file is produced for direct executor testing.

**Tech Stack:** Luau, Roblox GUI Instances, TweenService, UserInputService.

**Spec:** `docs/design/pilot-v0.1.md`

## Global Constraints

- First target environment: Potassium.
- No mandatory external dependencies.
- Re-execution must not leave duplicate Lumi UI roots.
- Pilot controls: button, toggle, slider, dropdown.
- Advanced systems such as configs, theme switching, notifications, and color picker are excluded from v0.1.
- UI implementation uses Roblox GUI Instances rather than a Drawing-only renderer.

## Review Focus

- Re-executing the script while an old Lumi root exists must cleanly replace it.
- Mouse drag must stop when input ends even if the cursor leaves the title bar.
- Slider values must clamp to the declared range and never divide by zero.
- Dropdowns with empty or single-item value lists must remain stable.
- A callback error must not corrupt the visual state of the control that invoked it.
